# 商城 API 与验收记录

## 通用约定

前缀 `/v1/market`，响应 `{ code: 0, message: "success", data: ... }`；失败同时返回非 2xx HTTP 状态与非零 code。分页参数 `current`、`pageSize`，每页最多 100 条，返回 `{ items, total }`。所有价格单位为分，所有资源 ID 为字符串。

除公开分类和商品外，均需 `Authorization: Bearer <token>`。商家归属和平台权限由服务器校验，不能由请求体提升权限。

| 方法 | 路径 | 用途 / 权限 |
| --- | --- | --- |
| GET | /catalog | 公开已审核商品；name、categoryId 筛选 |
| GET | /categories | 公开分类列表 |
| GET | /context | 当前身份、店铺、沙箱开关 |
| GET / POST | /shops | 我的店铺或平台列表；申请/驳回后重新申请 |
| POST | /shops/:id/review | 平台审核；status、reason、commissionBps |
| POST | /categories | 平台新增分类 |
| GET / POST | /products | 自有/全平台商品；商家发布 |
| PUT | /products/:id | 自有商品编辑，重新审核 |
| POST | /products/:id/review | 平台通过/驳回；店主可以下架 |
| POST | /products/:id/stock | 店主/平台调整库存；delta 为带符号整数 |
| GET / POST | /addresses | 当前用户地址 |
| DELETE | /addresses/:id | 删除自己的地址 |
| GET / PUT | /cart | 购物车；productId、quantity 设置目标数量 |
| DELETE | /cart/:id | 删除自己的购物车项 |
| POST | /checkout | addressId、cartIds、requestKey；事务拆单 |
| GET | /orders | scope=buyer/merchant/platform；可筛选 status |
| POST | /orders/:id/actions | action 和动作所需字段 |
| GET | /dashboard | 与订单相同的 scope，返回统计 |
| GET | /audit | 平台审计分页 |

独立认证接口 `/register` 接收 username、email、password、captchaId、captchaCode。验证码从 `/captcha` 获取；注册不接受任何角色参数。

## 订单动作

| action | 允许身份 | 前置状态 | 结果 | 额外字段 |
| --- | --- | --- | --- | --- |
| pay | 买家（仅沙箱） | 未过期 pending | paid | 无 |
| cancel | 买家 | pending | cancelled | 无 |
| ship | 正常店铺的店主 | paid | shipped | carrier、tracking |
| receive | 买家 | shipped | completed | 无 |
| refund | 买家 | paid/shipped/completed | refunding | reason |
| approve-refund | 店主/平台（仅沙箱） | refunding | refunded | 无 |
| reject-refund | 店主/平台 | refunding | 申请售后之前的状态 | reason |

## 验证范围

自动测试覆盖：

- 服务端计价、两店拆单、佣金及收货快照。
- 同一 requestKey 重放返回相同订单，参数不同则拒绝。
- 任一店缺货时整批回滚，保留购物车，允许修复库存后重试。
- 取消、过期、未发货退款只回补一次库存。
- 非本店编辑商品失败、编辑触发重新审核、编辑不覆盖库存。
- 未登录请求拒绝、普通用户不能审核、商家订单列表隔离。
- 订单状态机非法跳转、过期支付、冒充买家、重复退款拒绝。
- 前端付款开关、取消确认、加载失败、普通用户无审核操作。

SQLite 测试不能证明 MySQL 的行锁语义。`TestMySQLConcurrentReservation` 在未配置独立 MySQL 时明确跳过；该测试用于两个买家竞争最后一件库存的情况。本机 Docker 未运行，因此真实 MySQL 事务并发和完整浏览器到真实支付的验收未执行。

不属于已验证功能：真实支付、物流渠道、资金分账/提现、生产容量、真实证照审核、短信邮件发送。

## 消费者购物网站（web/mall-web）

独立消费者前端位于 `web/mall-web`，不与管理端共用页面或请求拦截器。使用 Node.js 22 及以上版本，在该目录执行：

```bash
npm install
npm run dev
npm test
npm run tsc
npm run lint
npm run build
```

本地开发代理将 `/v1/`、`/login`、`/register`、`/logout`、`/refresh` 和 `/captcha` 转发到 `http://localhost:9091`。生产部署时应由站点网关或同源反向代理提供 API 路由。

订单页仅在 API context 的 `sandboxPayment` 为 `true` 时显示“开发沙箱付款”，并持续说明该操作仅用于开发演示、不产生真实扣款。关闭沙箱时不显示付款操作。
