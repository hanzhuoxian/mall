# 商城代码结构调整

本次落实代码审查后的工程结构调整，保持现有接口路径、请求字段、状态码、业务状态流转、数据库表及约束不变。

## 后端

`internal/marketplace/model` 保存数据模型、输入与查询类型；`controller` 负责 Gin 请求解析、身份识别和响应；`service` 负责权限、校验、订单流转和事务编排；`store` 定义类型化存储接口，`store/mysql` 实现 GORM 查询。事务回调获得同一事务的存储实例，维持原有加锁顺序、回滚及幂等性。请求的 context 传到存储层。

成功响应复用 `response.Success`，失败通过 `response.Fail` 和错误码适配保留现有 HTTP/业务码及安全提示。API 服务通过构造函数注入依赖，关闭数据库与过期订单任务不再直接操作 handler 的数据库字段。

## 前端

将商城的十个业务入口拆分为独立页面，路由显式指定页面组件。提取共享加载逻辑、编辑器、状态展示及订单详情，接口请求统一放入 `service.ts`，领域类型替代通用 `any[]`。保持权限展示、付款开关、金额单位、确认操作、请求防竞态、结算幂等键和失败提示。

## 验证

先运行已有 Go 商城及 API 测试作为基线。调整测试导入和构造方式，保留原业务断言；补充 HTTP 错误响应及权限回归覆盖。运行 Go 测试、编译、格式及静态检查；运行前端 Vitest、TypeScript 与 Biome。需要外部 MySQL/Redis 的测试只在已配置隔离环境时执行，并明确报告跳过情况。
